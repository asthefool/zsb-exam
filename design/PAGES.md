> 用途：UI 设计输入。本文只描述**当前代码里真实存在的页面、区块、控件与状态**，不含设想的页面。

## 二、页壳（Layout）

### 2.1 考生端页壳 `StudentLayout.vue`

白底 sticky 顶栏（`max-width: 1120px`，背景 `rgba(255,255,255,.92)` + 毛玻璃），两行结构：

**第一行 · 品牌 + 用户区**
- 品牌：34×34 主色方块内白字「升」+ 17px 粗体「专升本智能备考」，点击回首页。
- 右侧用户 chip：`<el-dropdown trigger="click">`，显示昵称 + 首字头像（昵称兜底顺序：`nickname → username → 同学`）。菜单项：
  - `个人中心` → `/profile`
  - `后台管理` → `/admin/questions`（**仅管理员渲染**）
  - `退出登录`（divided 分隔）→ 清凭据并回 `/login`

**第二行 · 横向导航（`overflow-x: auto`）**，5 项，每项 = 内联 SVG 图标 + 文字，选中态为主色浅底 + 主色文字：

| 顺序 | 文案 | 图标隐喻 | 路径 |
| --- | --- | --- | --- |
| ① | 今日计划 | 列表横线 | `/` |
| ② | 智能题库 | 翻开的书 | `/practice` |
| ③ | 模拟考场 | 时钟 | `/exam` |
| ④ | 错题本 | 书签 | `/wrong-book` |
| ⑤ | 学情报告 | 柱状图 | `/report` |

**第三行 · 日期横幅**：一行 flex 两端对齐，文案 `` `${年} 年 ${月} 月 ${日} 日 周${week}` ``（周字用 `日一二三四五六`）。

**区外**：`<router-view />` 挂在 `max-width: 1120px` 的 `.page-wrap` 里（`padding: 24px 24px 48px`）。

**现状与设计缺口**
- **无移动端抽屉**：≤640px 只把内边距收到 14px、品牌字缩到 15px，导航仍是横向滚动的 5 个胶囊。手机上没有汉堡菜单。
- 无面包屑；无加载/错误态（`fetchProfile()` 静默失败）。

### 2.2 管理端页壳 `AdminLayout.vue`

Element Plus `el-container` 组合，**独立视觉体系**（与考生端不统一）：

- **左侧 `el-aside` 宽 220px**：白底 + 右边框。顶部品牌文字「后台管理」（18px / 600 / 主色）。`el-menu` router 模式，`default-active = 当前 path`，两项：`题目管理` → `/admin/questions`、`用户管理` → `/admin/users`。
- **顶栏 `el-header`**：左「专升本智能备考系统（管理端）」；右两个文字按钮 `返回考生端` → `/`、`退出` → 登出并回 `/login`。
- **`el-main`**：页面底色，内嵌 `<router-view />`。
- **无面包屑、无用户菜单、无移动端适配与折叠**（固定 220px，桌面专用）。

## 三、认证页（无页壳）

### 3.1 登录 `/login` — `PAGE-001`

**职责**：账号登录，按角色分流到 `/admin/questions`（管理员）或 `/`（考生）。

**骨架**：整屏两栏 `.login-wrap` —— 左侧品牌栏（≤860px 隐藏）+ 右侧居中卡片。

| 区块 | 内容与文案 |
| --- | --- |
| 左品牌栏（主色底） | 「升」品牌标记 + 「专升本智能备考」+ 标语「刷题练习、错题诊断、计划执行」 |
| 右表单卡 | `h2`「欢迎回来」+ 副标题「登录后开始今天的学习计划」 |
| 表单项 | 「用户名」`el-input` 占位「请输入用户名」；「密码」`el-input type=password show-password` 占位「请输入密码」 |
| 主按钮 | 通栏「登 录」（loading 态） |
| 底部 | 「还没有账号？」+ 链接「立即注册」→ `/register` |

**交互/校验**：`label-position="top"`，回车提交。规则（blur 触发，必填）：「请输入用户名」「请输入密码」。
**状态**：按钮 loading；登录失败**无页内错误区**，靠全局拦截器 toast（40102 等）；成功 `ElMessage.success('欢迎回来，{昵称}')` 后跳转。
**设计缺口**：无「记住我」「忘记密码」入口。

### 3.2 注册 `/register` — `PAGE-002`

同款两栏外壳，左栏文案一致。

| 区块 | 内容与文案 |
| --- | --- |
| 右卡标题 | `h2`「注册账号」+「创建账号，开始你的备考之旅」 |
| 表单 4 项 | 「用户名」占位「3-32 位字母、数字或下划线」；「昵称（可选）」占位「用于展示，可随时修改」（`maxlength=32`）；「密码」占位「至少 6 位」；「确认密码」（无占位） |
| 主按钮 | 通栏「注 册」（loading 态） |
| 底部 | 「已有账号？」+「去登录」 |

**校验规则**（blur）：
- 用户名：必填「请输入用户名」；`/^[a-zA-Z0-9_]{3,32}$/` → 「3-32 位字母、数字或下划线」
- 密码：必填「请输入密码」；≥6 → 「密码长度至少 6 位」
- 确认密码：必填「请再次输入密码」；自定义校验 → 「两次输入的密码不一致」

**状态**：按钮 loading；成功提示「注册成功，请登录」后跳 `/login`；失败（如用户名重复）走全局 toast。无确认弹窗。

## 四、考生端页面

### 4.1 今日计划 `/` — `Home.vue` — `PAGE-003`
**职责**：学习概览仪表盘（信息密度最高的一页，最适合用来定层级体系）。区块自上而下：

**① 问候区**（无卡片）
- `h1`「早上好，{昵称}」——**注意：硬编码「早上好」，不随实际时间变化**（设计时可考虑改成动态问候或去掉时段词）。
- 副行三选一：`已持续备考 {n} 天，距离考试还有 {n} 天。` / `已持续备考 {n} 天` / `今天也要加油备考。`

**② 错误提示条**（条件）：`el-alert type=error` 标题「学习概览加载失败」+ 内嵌按钮「重新加载」。

**③ 四张统计卡**（`label` / `value` / `foot`）：

| 标签 | 数值 | 脚注 |
| --- | --- | --- |
| 距离考试 | `{n}` + 单位「天」（无则 `—`） | 考试日期 `YYYY-MM-DD`，或「尚未生成复习计划」 |
| 今日完成 | `{done}/{total}` + 单位「项」 | 「进度 {n}%」或「暂无今日任务」 |
| 累计做题 | `{n}` + 单位「道」 | 「正确率 {n}%」 |
| 未掌握错题 | `{n}` + 单位「道」 | 0 时「继续保持」（绿色 `.up`），否则「建议今日回炉」 |

**④ AI 建议条**：主色浅底方块「AI」+ 标题「AI 建议」+ 引擎标签（`真实大模型` 绿 / `规则引擎（模拟）` 蓝灰）+ 建议正文（规则生成，如「你还有 N 道未掌握的错题，建议优先回炉重练」「当前计划完成 {done}/{total}，今日任务记得打卡」「近期正确率 N%，状态不错，可以适当提高难题占比」，兜底「开始刷题后，这里会根据你的错题分布给出学习建议」）+ 右侧按钮「查看错题」→ `/wrong-book`。

**⑤ 两栏网格**
- 左卡「今日学习计划」：副信息「共 N 项」+ 文字按钮「管理计划」→ `/plan`。任务行（整行可点，已完成的加对勾、时间、内容、右侧「已完成」绿标签 /「打卡」蓝标签 /「打卡中」）：时间槽（空显示「待定」）+ 内容 + 状态标签。空态两种：无生效计划 →「还没有生效中的复习计划」+ 主按钮「去生成复习计划」；有计划无今日任务 →「今天没有安排任务，可到计划页查看完整安排」+ 按钮「管理计划」。
- 右卡「未来七日任务」：副信息「共 N 项（已完成 M）」。7 根柱状图（柱顶 `done/total`，柱高按比例，最低 10%，当日 0 项时用浅色 muted），柱下日期标签（今天 / 日一二三四五六）。空态「生成复习计划后，这里会按天展示任务安排」。

**⑥ 两栏网格**
- 左卡「科目掌握度」：副信息「竖线为目标 85%」。科目胶囊行（`{科目名}` + 加粗掌握度数字，选中高亮）→ 该科目进度条（带 85% 目标竖线 + `{n}%`）→ 选中科目块：`h3「{科目}优先攻克」` + 小按钮「专项练习」→ `/practice?subject=<id>` + 弱项列表（`{题干}` + 红标签「错 N 次」），空态「该科目暂无未掌握错题，继续保持」。
- 右卡「每日一题」：右上文字按钮「换一题」（loading 态）。元信息标签：题型「单选/多选/判断」+「难度 {n}」。内嵌 `QuestionCard`（无边框、隐藏元信息）。空态「题目加载中……」（加载中）或「暂无题目」。

**状态**：整页 `v-loading`；每日一题独立 `v-loading`；错误条 + 重试；多处空态（见上）；打卡成功后标签翻绿（乐观更新，无 toast）；无确认弹窗。
> ⚠️ 掌握度口径：当前算法为 `(该维度题量 − 未掌握错题数) ÷ 题量`，用 24 道种子题演示时恒在 90% 以上，进度条几乎全满，表达不出「某科偏弱」。SPEC.md 已建议改为正确率口径 —— 设计稿出图前需确认用哪套数。

### 4.2 智能题库 `/practice` — `Practice.vue` — `PAGE-004`
**职责**：筛选题库 → 开一轮 10 题练习（`SESSION_SIZE = 10`）→ 逐题判分。**两种互斥形态：答题中（session）与题库面板（bank）**。支持 `?subject=<id>` 预选科目。

**① 页头**：`h1`「智能题库」+「按科目刷题，AI 会根据正确率自动推荐下一组练习。」+ 右侧主按钮「智能组卷」→ `/exam?smart=1`。

**② 筛选胶囊卡**（常驻）
- 第 1 行科目：`全部科目` + 每科一个胶囊。
- 第 2 行题型：`全部题型` / `单选题` / `多选题` / `判断题`。
- 切换筛选会**清空当前答题轮次**并重拉统计。

**③-A 答题形态**（`session` 存在）
- 卡片标题「{session.title}」（如「全部科目」「高等数学（单选题）」「简单练习」「混合自测」）；副信息「本轮 N 题，已答对 M 题」+ 文字按钮「退出练习」。
- 内嵌 `QuestionCard`（隐藏元信息，判分后展开解析），键 `practice-<id>`。
- 底部动作条：左「第 {i+1} / N 题」；按钮「上一题」（首题禁用）、「下一题」（主色，**当前题未答则禁用**），末题变「完成本轮」。
- 全部答完的横幅：「本轮完成：答对 M / N 题」+ 按钮「再来一组」（主色）、「返回题库」。

**③-B 题库面板形态**（默认）
- 错误条（条件）：标题「题目加载失败或当前筛选下暂无题目」+ 按钮「重新加载」。
- 左卡「题型进度」：副信息「{科目名}，未掌握错题 N 道」。三行（单选题/多选题/判断题）：名称 + 灰字「共 N 题」+ 进度条 + 脚注「掌握度 {n}%」+ 条件红标签「未掌握 N」；行尾按钮「继续刷题」（**该题型 0 题时禁用**）。
- 右卡「推荐练习」：头部 `el-select` 宽 120px（`全部难度` / `简单` / `中等` / `困难`，**当前是空操作**）；四行推荐：
  - 「错题回炉」+ 红标签「N 道未掌握」+ 灰字「优先重练高频错题」+ 按钮「开始」（未掌握为 0 时禁用）→ `/wrong-book?subject=<id>`
  - 「简单练习 / 中等练习 / 困难练习」各行 + 同色蓝标签 + 灰字「约 10 题，约 {n} 分钟」+ 按钮「开始」→ 开对应难度轮次
  - 「混合自测」+ 标签「随机抽题」+ 灰字「跨题型混合 10 题」+ 按钮「开始」

**状态**：开轮 loading；错误条 + 重试（0 题也用同一个错误条，属语义混用）；禁用态（上一题 / 未答的下一题 / 无题型的继续刷题 / 0 未掌握的错题回炉）；答题反馈由 `QuestionCard` 的「✓ 回答正确 / ✕ 回答错误 + 正确答案 + 题目解析」承担；无确认弹窗（「退出练习」无二次确认）。

### 4.3 模拟考场 `/exam` — `MockExam.vue`（新增页，旧 review 未覆盖）
**职责**：全真计时考试。**三种互斥形态：试卷列表 / 考试中 / 成绩单**。支持 `?smart=1` 自动开始智能组卷。

**形态 A · 试卷列表**（默认）
- 页头：`h1`「模拟考场」+「全真计时，交卷后 AI 逐题解析并更新你的预估分。」
- 三组分组（组标题 + 两列卡片网格）：

| 分组 | 试卷名 | 科目 | 题量 | 限时 | 满分 |
| --- | --- | --- | --- | --- | --- |
| 模拟卷 | 智能组卷（综合自测） | 综合 | 10 | 20 分钟 | 100 |
| 模拟卷 | 2027 专升本全真模拟卷（一） | 综合 | 10 | 30 分钟 | 150 |
| 模拟卷 | 2027 专升本全真模拟卷（二） | 综合 | 10 | 30 分钟 | 150 |
| 历年真题 | 2025 年统考真题 | 综合 | 10 | 25 分钟 | 150 |
| 历年真题 | 2024 年统考真题 | 综合 | 10 | 25 分钟 | 150 |
| 专项卷 | 高等数学阶段测验（极限与导数） | 高等数学 | 8 | 20 分钟 | 100 |
| 专项卷 | 大学英语阅读专项 | 大学英语 | 8 | 20 分钟 | 100 |

- 卡片：试卷名（粗体）+ 元信息「{科目}，共 N 题，限时 M 分钟」+ 页脚两态：有历史分 → 粗体「{score} / {full}」+ 灰字「上次得分」+ 主色文字按钮「重新作答」；无历史分 → 标签「未开始」+ 主按钮「开始考试」。

**形态 B · 考试中**
- 考场条：左 `h2`「{试卷名}」+「共 N 题，满分 M 分」；右倒计时「剩余 MM:SS」（**≤5 分钟变红 urgent**）+ 灰字「已作答 {a}/{n}」+ 主色按钮「交卷」。
- 两栏（240px + 1fr）：

## 六、全局复用组件（设计只需画一套，多处复用）

### 6.1 `QuestionCard.vue` —— 答题卡（**5 处复用**）

复用位置：每日一题（首页）、智能题库答题轮、错题本抽屉、模拟考场答题、模拟考场逐题解析。

**Props**：`question`（必填：`id`/`q_type`/`content`/`difficulty`/`options`）、`result`（判分结果，传入即锁定卡片）、`plain`（去卡片边框内边距）、`hideMeta`（隐藏题型与难度标签）、`examMode`（只选中不判分）、`initial`（考试模式切题回填）。
**Emits**：`submit`（`{question_id, user_answer}`）、`picked`（考试模式每次选择变化）。
**Slots**：无。

**渲染顺序与形态**
1. 元信息行（`hideMeta` 时隐藏）：蓝标签题型「单选/多选/判断」+ 标签「难度 {n}」
2. 题干（15px，`pre-wrap`）
3. 选项列表：真实 `<input type=radio>`（单选，`role=radiogroup`）/ `<input type=checkbox>`（多选）；每行 = 字母键 `A/B/C/D` + 文本。**四态**：默认 / `selected`（主色底主色边）/ `right`（绿）/ `wrong`（红）；判分后 `locked`（禁用但仍保留各自配色，正确项一律标绿，含「正确但没选」的项）
4. 判断题兜底：模板写死的两行 `√ 正确` / `× 错误`
5. 提交按钮「提交答案」（仅 `!result && !examMode` 时出现；未选禁用）
6. 判分条：绿条「✓ 回答正确」/ 红条「✕ 回答错误」+ 副文案「正确答案：{答案}」（判断题人性化为「正确（√）」/「错误（×）」）
7. 解析块（`result.analysis` 存在时）：标题「题目解析」+ 正文

**状态**：未答（提交禁用）→ 已答锁定；对/错两色；考试模式（无提交、无判分、可回填）；切题时练习模式重置选择、考试模式回填 `initial`。
> ⚠️ 已知风险：`options` 若非数组而是**无法解析的 JSON 字符串**，会静默退化成 0 个选项 → 单选题会错渲染成「正确/错误」判断题形态。设计上可要求加「选项数据异常」提示位。

### 6.2 `ExplainPanel.vue` —— AI 错题讲解面板（**1 处复用**，错题本抽屉）

**Props**：`wrongQuestionId`（必填）。**Emits**：`explained`。**Slots**：无。
内部显式状态机 `loading | success | failed`，三套互斥模板：

1. **加载态**：`el-skeleton :rows=6 animated` + 提示「AI 讲解生成中，最多约需 30 秒，请稍候……」
2. **成功态**：标签「来源：{provider}」+ 条件标签「缓存」；正文 `<pre>`（浅底，保留换行）；条件警告条「重新生成失败：…」（**旧内容仍保留在下方**）；按钮「重新生成」（loading）；免责声明「⚠️ AI 生成，仅供参考」
3. **失败态**：`el-alert type=error` 标题「AI 讲解生成失败」，描述按错误码映射：「请求过于频繁，请稍后再试」（42901）/「AI 服务未配置，请联系管理员」（50202）/「AI 上游服务暂不可用，请稍后重试」（50201）/ 兜底「上游服务暂不可用，请稍后重试」；下方主按钮「重试」

成功且非缓存时 toast「讲解已生成」。
> 💡 **给设计的建议**：后端 prompt 与 mock 引擎都**强制输出三段固定小标题** —— `## 一、错因分析` / `## 二、解题思路与步骤` / `## 三、知识点提示`（见 `server/src/ai/prompts/explain.md` 与 `ai/mockProvider.js`）。前端目前用一个 `<pre>` 整段糊出，把它按 `## ` 切成三段带图标的小节卡会显著提升质感，**且不需要改后端**。

## 七、功能模块（后端分组 → 页面映射）

| 模块 | 后端文件 | 接口数 | 对应用户可见能力 |
| --- | --- | --- | --- |
| 用户域 | `routes/auth.js` · `services/authService.js` · `userService.js` | 6 | 注册 / 登录 / 登出 / 查看与修改资料 / 首页概览 |
| 题库域 | `routes/exam.js` · `questionService.js` · `answerService.js` | 3 | 科目列表 / 题目分页筛选 / 提交答案并判分 |
| 错题域 | `routes/exam.js` · `wrongService.js` | 4 | 错题列表与详情 / 错题重练 / 标记掌握 |
| 计划域 | `routes/plan.js` · `planService.js` · `dao/planDao.js` | 4 | 生成计划 / 当前计划 / 历史计划 / 任务打卡 |
| AI 服务域 | `routes/exam.js` · `aiService.js` · `ai/mockProvider.js` · `ai/llmProvider.js` · `ai/planEngine.js` | 3 | 查询引擎模式 / 读取讲解缓存 / 生成讲解 |
| 管理端 | `routes/admin.js` · `adminService.js` | 6 | 题目 CRUD（软删）/ 用户列表 / 启用禁用 |

**横切能力（会出现在多个页面，设计应统一）**
- **AI 双模式**：`mock`（规则引擎，零依赖）/ `llm`（真实大模型）。所有涉及 AI 的位置都必须能显示「规则引擎（模拟）」与「真实大模型」两种身份标签 —— 首页 AI 建议条、复习计划卡头。（SPEC.md 用「AI 面板」这一组件统一承载。）
- **AI 生成免责声明**：「⚠️ AI 生成，仅供参考」出现在讲解面板与学情报告诊断结论两处。
- **鉴权与错误码**：40101（未登录/令牌过期→弹回登录）、40301（角色不足→回首页）、42901（限流）、50201/50202（AI 上游/未配置）。前端由 `api/request.js` 统一拦截 toast，**页面内错误区只覆盖「加载失败 + 重新加载」这一种**。
- **题型常量**：`constants.js` 的 `{ single: '单选', multiple: '多选', judge: '判断' }`；题型标签在 6 个页面出现，应做成一个标签组件。
- **难度语义**：题库数据里是 1–5（管理端用 5 星 `el-rate`），但前端推荐卡片和每日一题只展示「简单/中等/困难」三档。**两套刻度需要设计上对齐规则**。

## 八、设计系统现状（换肤的起点）

### 8.1 当前视觉基调（`web/src/style.css`）
「蓝白教育平台风」：页面底 `#F5F7FB` / 卡片 `#FFFFFF` + `#E3E8F0` 细边框 / 圆角 12px / 单一品牌蓝 `#1D4FD7` / 文字 `#0F1A2B` 与 `#5B6779` / 绿 `#12805C` 与红 `#C0352B` 只表示对错。**单一无衬线字体**（`Noto Sans SC` 起头）。

> ⚠️ **字体实际未加载**：`web/index.html` 里没有引入任何 Web Font，`:root --font` 引用的「Noto Sans SC」在本机多半不存在，实际渲染回落到系统字体（Windows 上是微软雅黑）。设计若要定字体，必须同时补 `index.html` 的字体引入（自托管或 CDN）。

### 8.3 设计前需确认的 5 个问题（都来自代码事实）

1. **掌握度口径**：现算法 `(题量 − 未掌握错题) ÷ 题量` 恒在 90%+，进度条无表达力。是否改为正确率口径？（影响首页「科目掌握度」与题库「题型进度」两处）
2. **「复习计划」是否补进主导航**：现在只能从首页进，闭环缺一个入口。（影响页壳导航结构）
3. **管理端是否沿用考生端视觉**：现在两套外壳完全独立（顶栏导航 vs 侧栏菜单）。SPEC.md 的主张是统一外壳。
4. **难度刻度**：数据是 1–5，展示只用了三档（简单/中等/困难）。设计要定映射规则与是否展示 5 星。
5. **学情报告的合成数据标注**：预估分趋势已改为真实数据；AI 诊断结论仍是示例性内容，设计稿要不要保留对应的诚实标注。
